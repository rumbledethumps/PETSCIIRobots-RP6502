# The unit overlay, and picking a level from the menu.
#
# DRAW_MAP_WINDOW plots the terrain and then, where a mobile unit stands, plots
# the unit's tile over it with PLOT_TRANSPARENT_TILE -- which writes a cell only
# when its glyph is not $3A, and skips past the ones it leaves alone with two
# reads of the data register. That is the one path in src/plot.s the other tests
# never reach: nothing in level-a puts a robot inside the window anywhere the
# player can walk to, and doors and found objects are written into the map
# rather than drawn over it.
#
# level-g starts the player at 51,33 with a robot already in view, so it reaches
# the path on the first frame. Getting there also exercises the map option on
# the intro menu, which nothing else does.

wait "MENU"
run 30

# Down to CHANGE MAP, then space six times: a to g.
press k
run 6
release k
run 10
press space
run 6
release space
run 10
press space
run 6
release space
run 10
press space
run 6
release space
run 10
press space
run 6
release space
run 10
press space
run 6
release space
run 10
press space
run 6
release space
run 10

# Back up to START GAME and go.
press i
run 6
release i
run 10
press space
run 6
release space

wait "BRINGUP OK"
run 10

# level 6, player at 51,33, 23 robots, window at 46,30, and something drawn over
# the terrain -- which is what the rest of the suite never gets to see.
peek xram:$FE03 $06
peek xram:$FE04 $33 $21
peek xram:$FE07 $17
peek xram:$FE0A $2E $1E
peek xram:$FE0E $01

# The robot at 48,30 is window tile (2,0), character columns 6 to 8 of rows 2 to
# 4. Its tile has four opaque cells and five transparent ones, so the right
# answer is a mixture: four cells of robot and five of the terrain underneath,
# in the exact places the tile says. Getting the skip wrong in either direction
# -- writing through it, or skipping the wrong number of bytes -- moves these.
peek xram:$96AC $93 $01 $3A $05 $20 $01
peek xram:$96FC $3B $05 $81 $0D $6A $0F
peek xram:$974C $20 $01 $76 $0F $3B $05
