# Music and sound effects on separate oscillators.
#
# The PET had one voice, so PLAY_SOUND parked the song's position and STOP_SONG
# put it back: the music went silent for the length of every beep, and the beep
# could not start until the music's row ended, up to seven frames later. The RIA
# has eight oscillators, so the two run on their own timers here.
#
# Everything below is read from the PSG registers rather than from engine
# variables in RAM, because those move whenever the link layout changes and this
# test should not. Oscillator 0 is at XRAM $FF00 and oscillator 1 at $FF08,
# eight bytes each: frequency as hertz times three, duty, the two envelope
# bytes, waveform and release, then the pan/gate byte whose bit 0 is the gate.

wait "MENU"
run 30
press space
run 6
release space
wait "BRINGUP OK"
run 60

# In game, level music playing, no effect. The two voices are already
# distinguishable by timbre: the music is a square held at a steady level
# ($80 $20 $20 $11), the effect voice a thin pulse that decays to a quieter
# sustain and releases fast ($30 $10 $30 $13). Effects need that edge now that
# the music no longer stops for them. Oscillator 1's gate is clear.
peek xram:$FF02 $80 $20 $20 $11 $01
peek xram:$FF0A $30 $10 $30 $13 $00

# F1 cycles the weapon, which plays SFX_CYCLEWEAPON.
press f1
run 2
release f1
run 3

# The effect strikes on oscillator 1 -- gate set -- while oscillator 0 holds the
# note it was already playing. Under the PET's arrangement these eight bytes
# would now belong to the effect.
peek xram:$FF08 $2F $08 $30 $10 $30 $13 $01
peek xram:$FF00 $56 $04 $80 $20 $20 $11 $01

# Six frames on, the song has moved to its next note while the effect is still
# running and has moved to its own. Two timers, neither waiting for the other.
run 6
peek xram:$FF00 $DD $03
peek xram:$FF08 $CA $05
peek xram:$FF0E $01

# The effect ends on its own and releases its own voice.
run 30
peek xram:$FF0E $00
